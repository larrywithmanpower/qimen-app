## 驗收項目

| 項目 | 結果 | 備註 |
|------|------|------|
| **[BE]** 外部 Origin 打 proxy 回 403 / CORS reject | ✅ pass | `curl -H "Origin: https://evil-site.com"` → HTTP 403；OPTIONS preflight 同樣 403 |
| **[BE]** 同一 IP 連送 11 次，第 11 次回 429 | ❌ skip | 本機無 Firestore 連線，`isRateLimited` 進入 catch fallback 回傳 `false`，rate limit 本機自動 bypass（by design）。代碼邏輯正確（`RATE_LIMIT_MAX=10`，超限 return `true` → HTTP 429），但無法在本機實際觸發。需 GCP 環境或 Firestore 模擬器驗收 |
| **[BE]** Cloud Function log 出現 `context` 與 `promptVersion` 欄位 | ✅ pass | 本機 log 已驗證：帶 context 時輸出 `proxy request {"context":"love","promptVersion":"v1"}`；不帶時輸出 `{"context":null,"promptVersion":null}` |
| **[FE]** `src/services/prompts/v1/` 全部 6 個檔案存在 | ✅ pass | `base.ts`, `contexts/love.ts`, `contexts/career.ts`, `contexts/invest.ts`, `schema.ts`, `registry.ts` 全部存在 |
| **[FE]** `npm run build` 零錯誤、零 TypeScript 錯誤 | ✅ pass | `tsc -b && vite build` 成功，無任何 TS error（chunk size 警告非錯誤，不計） |
| **[FE]** aiService 舊介面回歸：不傳 contextKey 仍正常呼叫，不 crash | ✅ pass | `contextKey` 為 optional，預設 `'general'`；`getContextByKey('general')` 走 `?? ''` fallback 回傳空字串；`buildSinglePalacePrompt` 以空字串跳過 context section，整個呼叫流程不 crash |

---

## 結論

共 6 項驗收標準，5 項通過，1 項無法在本機環境驗證（**BE rate limit 429**）。

Rate limit 功能的代碼實作邏輯正確，但 Firestore-based 的限速機制在本機開發環境下由設計上 bypass，必須在有 Firestore 連線的環境（GCP Cloud 部署或 Firestore emulator）才能完整驗收「第 11 次回 429」這項。

**建議行動：**
- 需在 GCP 部署後或設置 Firestore emulator，重新執行 rate limit 測試
- 已為此項目建立 follow-up issue，原 issue LDE-123 設為 `blocked`
